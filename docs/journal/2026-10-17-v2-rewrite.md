# 2026-10-17: v2 rewrite

> **Answers**: why the v2 is built this way · what was read on the site · which defects the tests found during the rewrite.

Dated story: it is never rewritten. A fact that becomes wrong is corrected in a new file.

## Request

Rebuild the Duo.GG helper extension with the working framework of three projects of the owner: BotEd_MDF (Chrome extension, Neon, documentation per task), ClimStock (monorepo, agent routing, green light) and a company functional documentation (generated layer, pointers to the code, two routers). Add a panel that hides instead of deleting, one-click posting, more results, and a Neon database per player.

## Decisions

| Decision | Origin | Reason |
| -------- | ------ | ------ |
| plain JS, no build, IIFE modules | BotEd_MDF | Chrome loads the working folder, an agent compiles nothing |
| `extension/` folder separate from the tooling | new | `node_modules/` and `docs/` out of the package |
| service worker as the only writer and only Neon client | BotEd_MDF, hardened | in v2, the connection string no longer touches the page |
| RLS per login role | new | several players in one database, without seeing each other |
| `docs/generated/` layer | company documentation | a list taken from the code is not copied |
| checked `src:` pointers | company documentation | a sentence of the documentation names the code that makes it true |
| symptom router `01-SYMPTOMS.md` | company documentation | troubleshooting starts from the displayed message |
| green light, one version per PR | BotEd_MDF, ClimStock | unchanged |
| linkedom and PGlite as test dependencies | new | captures replayed, SQL and RLS run |
| repository in English, conversation in French | company documentation | the code, the site and the API use English. `npm run check` refuses accented letters. |

## Readings on the site

Read in Chrome, signed in, read-only:

- The table holds 50 posts, without pagination or infinite scroll.
- The data comes from `https://duo.op.gg/graphql`, operation `partners`.
- `from: 50` returns an empty list. `from` equal to the Unix timestamp of the oldest post, in seconds, returns the next 50.
- `from: 0` returns an empty list as soon as a native filter is active. Without `from`, page 1 of the API matches the 50 rows of the table, with the Support filter on.
- `tier` and `position` at null return an empty list. `ALL` returns everything.
- `insertedAt` comes as ISO on one page, as Date text on another.
- `requiredPosition` is sometimes null: the Looking for cell is then empty.
- The `AddPartner` mutation publishes a post. The form was neither opened nor submitted: one-click posting waits for a reading by the owner ([`../project/todo.md`](../project/todo.md)).
- Live probe, DOM extractor against the API on the same 50 posts: zero difference on name and tag, position, rank, wins and losses, wanted positions, KDA, OpScore, age and note.

## Defects found by the tests during the rewrite

| Defect | Test | Fix |
| ------ | ---- | --- |
| the pseudonymization numbered the tags in order: a player who posted twice got two identities | `extract.test.mjs`, expected duplicate | identity = name and tag |
| a player with zero games had a win rate of 0 | `extract.test.mjs` | win rate null |
| `data-duogg-why` rewritten at each recompute restarted the observer under linkedom | `page.test.mjs`, process that never ends | write only what changes |
| `#duogg-more` rewritten at each recompute: same loop | `page.test.mjs` | content signature, "no loop" test added |
| the first page of Show more asked for `from: 0`, empty with an active native filter | live probe: DOM extractor against the API on the same posts | first page without `from`, test added to `api.test.mjs` |
